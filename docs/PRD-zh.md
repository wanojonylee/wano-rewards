## 2. 背景与机会

**巴西没有押金制。** 与德国 Pfand、北欧 DRS 不同，巴西消费者投瓶无法定退款，"把瓶子送回机器"对个人没有经济理由，回收量完全依赖外部激励。这决定了产品形态：**RVM 本身不产生回收行为，App 才产生回收行为。**

**供给侧逻辑已成立。** 据 `RVM Requirements.txt` §P2，EK 把 RVM 卖给公寓、超市、快餐店，设备就地研磨，材料收入归场所业主，目标 5 年回本（§43）。场所愿意装机，因为能拿材料钱与 ESG 数据。

**但需求侧是空的。** 机器装了，人不投。这是 WANO Rewards 存在的唯一理由。

**为什么必须做 App：** ① 屏幕接触仅 15–40 秒，承载不了账户、历史、榜单与规则；② 积分必须有"可累积、可查询、可兑换"的载体，否则激励在离机瞬间归零；③ 品牌方（Danone/Coca-Cola/Vigor/Yakult，§27）要可归因到人、可结算的对象，屏幕只给曝光（§29），App 才给转化；④ 迷你超市（§28）要"投瓶→券/余额→当场消费"闭环；⑤ §31–§37 的参与率与 SKU 返还率都需用户维度；⑥ 千台网络的满箱调度、故障告知、活动灰度需直达用户的通道。

**商业闭环（唯一主线）：**

```
投瓶（扫码会话）→ 积分/返现实时入账（双账本）→ 兑换（迷你超市券/品牌实物/体验/捐赠）
   → 下一次到店 → 再投瓶 → 等级与排名上升 → 邀请传播
                        ↑                              ↓
              品牌活动预算（Danone 等）←── 可归因数据 ──→ EK 与场所报表
```

闭环资金来自三处：**材料收入（基础积分）＋ 品牌预算（活动加成）＋ 场所补贴**。第 7 节将证明：仅靠材料收入无法支撑有感知的奖励，这是本项目最重要的经济结论。

## 3. 产品定位与价值主张

**定位：** 巴西无押金市场的"回收即收益"消费级账户体系，同时作为欧洲 DRS 市场的白标底座。

**一句话价值主张：** 投一个瓶子，三秒见收益，楼下就能花掉。

| 语言 | Slogan | 场景 |
|---|---|---|
| EN（主） | **Deposit. Earn. Repeat.** | 商店副标题、开屏 |
| PT-BR（本地主推） | **Recicle, ganhe, troque.** | 巴西全部物料 |
| 中文（内部） | 投瓶即收益，回收有回报 | 客户汇报 |
| EN（备选，ESG 叙事） | Every bottle becomes a benefit. | 品牌方与物业提案 |

| 维度 | 巴西版 | 欧洲 DRS 版 |
|---|---|---|

## 5. 范围

**MVP（本期，对齐 `api-contract.md` v1）：** OTP 登录与 LGPD 同意、扫码会话与实时投瓶、积分与返现双账本、四级等级、品牌活动与三级排行榜、奖励商城（券/实物/体验/捐赠）、兑换码与核销、迷你超市支付码、Stripe 充值、PIX 提现、邀请、通知中心、机器地图、ESG 个人报告、设置、数据导出与注销、运营后台。

**P1（Pilot 后 1 季度）：** WhatsApp OTP/通知；离线会话缓存与补偿工单；任务与 streak；活动预算熔断与紧急下线；多语言内容管理（不发版）；提现月限额与分级 KYC；实物物流跟踪；楼栋管理员轻量视图（PWA）；收据下载。

**P2：** 欧洲 DRS 模式与押金凭证；玻璃与多材质流；团体/企业积分池；品牌方自助投放后台；POS 开放 API；Wallet 卡券；深度无障碍增强。

**Out of scope：**

| 不做项 | 归属 |
|---|---|
| 整机 HMI 界面（投瓶动画、拒收屏） | 整机软件（PLC/工控机），本 PRD 只定义数据契约 |
| 视觉识别 / NIR / 称重算法 | 整机侧（§1–§6），App 只消费结果 |
| 回收商端（MTR、称重对账） | §39，独立后台 |
| 广告投放后台与素材管理 | §29，EK 侧 CMS；App 只做落地页 |
| 真实资金清算开户 | MVP 用 Stripe 测试模式；生产需巴西主体 + PSP |
| 完整 KYC（证件 OCR、活体、制裁名单） | MVP 只做 CPF 校验 + 阈值人工；P1 接第三方 |
| 税务计算与 NF-e 开具 | EK 财务系统，App 只导出数据 |
| 客服坐席系统 | 第三方（Zendesk 等），App 只做入口 |

**边界划分：** App 唯一归属用户身份与账户；整机只上报"接受/拒收 + 重量 + GTIN + eventId"，不计算积分；EK 云按 §24 拥有全部运营数据与导出权，可无锁定获取。**关键约束：积分从不在整机计算**——设备被篡改也无法伪造发奖。

### 6.2 三个必须做对的细节

**双账本口径：** `points` 是营销货币（可过期、可倍率、不可提现），`creditCents` 是钱（可消费、部分可提现）。二者禁止隐式互换；若允许"积分兑返现"，必须显式定价、单列预算科目、披露兑付率，否则负债无法计量。

**`withdrawableCents` 的定义：** 只累计"材料收入转化的返现"与"品牌活动现金返现"；充值、邀请奖励、客服补偿一律不可提现。这既是反洗钱第一道闸，也是商店审核时区分"虚拟币"与"真实余额"的依据。

**兑换幂等与时效：** 所有核销须服务端幂等；券到期退回由定时任务执行，退回分录必须能与原扣分分录配对，否则月末必然账实不符。

## 7. 积分与返现经济模型

### 7.1 发放规则

| 规则 | 数值（可配置） | 说明 |
|---|---|---|
| 按件 | PET/PS/HIPS 2 积分；铝罐 3 积分 | 主规则，最易理解 |
| 按重量 | 5 积分/kg | 与件数叠加，抑制"轻瓶刷量" |
| 活动倍率 | 1.5×–3×，按材质/品牌/SKU | 由品牌预算支付，不计入材料成本 |
| 等级倍率 | 1.0/1.1/1.25/1.5 | 只作用于基础积分 |
| 单用户日上限 | 500 积分（约 250 件） | 超出不计分，提示已达上限 |
| 现金返现 | 材料收入 × 3%（约 BRL 60/台/月） | 入 `creditCents`，可提现 |

### 7.2 1 积分的定位

1 积分**内部影子价值 = BRL 0.010**（100 积分 ≈ BRL 1.00 券面），仅用于预算、负债计量与奖励定价，**不对用户承诺固定汇率**——一旦承诺即成可诉债权，且无法随通胀与汇率调整。用户侧只展示"积分"与"能换什么"。

### 7.3 成本占材料收入上限

| 层级 | 上限 | 触发动作 |
|---|---|---|
| 发放预算（面值） | 材料收入 × **20%** | 超限自动下调基础规则 10% |
| 已兑付成本（现金流出） | 材料收入 × **15%**（红线） | 超限冻结活动加成，人工复核 |
| 现金返现 | 材料收入 × **3%** | 独立科目，不与积分混算 |

### 7.4 可算示例（单台/月，公寓场景）

**假设（需 EK 按月确认，非承诺值）：** 每台每月 600 kg；按重量 PET 70%/PS·HIPS 20%/铝 10%；单价 PET BRL 3.10、PS·HIPS 2.30、铝 7.20 每 kg；平均 33 g/件（约 18,000 件/月）。

| 项目 | 计算 | BRL/月 |
|---|---|---|
| PET 收入 | 420 kg × 3.10 | 1,302 |
| PS/HIPS 收入 | 120 kg × 2.30 | 276 |
| 铝收入 | 60 kg × 7.20 | 432 |
| **材料收入合计** | | **2,010** |
| 换箱与物流 | 3 次 × 60 | −180 |
| 联网与软件 | 固定 | −90 |
| 维护计提 | 年 1,800 摊销 | −150 |
| 积分成本（已兑付） | 见下 | −257 |
| **站点净贡献** | | **1,333** |
| 设备 + 安装（假设） | 待报价 | 90,000 |
| 静态回本 | 90,000 ÷ 1,333 | **≈ 67 个月（5.6 年）** |

**积分发放与兑付：**

| 步骤 | 计算 | 结果 |
|---|---|---|
| 发放预算上限 | 2,010 × 20% ÷ 0.010 | 40,200 积分 |
| 件数发放 | 17,000 × 2 + 1,000（铝）× 3 | 37,000 积分 |
| 重量发放 | 600 × 5 | 3,000 积分 |
| 合计 | | 40,000 积分 ≈ BRL 400（19.9%） |
| 兑付率（12 个月） | 假设 | 65% |
| 已兑付成本 | 40,000 × 65% × 0.010 | **BRL 260（12.9%，低于 15% 红线）** |

**必须写进客户汇报的结论：** 材料收入只能支撑约 200 积分/户/月，折合约 BRL 2/户/月，**不足以驱动行为**。产品因此必须：① 用排行榜、streak、等级把非现金价值做大；② 用品牌预算把单件奖励提到 3–8×；③ 用迷你超市把积分变成"当场能用的东西"。这就是 §27 品牌活动不是营销附加项、而是商业模式必要条件的原因。

### 7.5 过期与负债

- **过期：** 自获得月起 12 个月，FIFO 消耗；T-30/T-7 两次提醒；过期前 7 天不受活动倍率影响。
- **计量：** 月末未兑付积分 × 0.010 × 预期兑付率（初期 65%，稳定后按实际回溯校准）。
- **规模：** 1,000 台稳定期月发 4,000 万积分，滚动未兑付约 3 个月 = 1.2 亿积分 = BRL 120 万面值 ≈ **BRL 78 万计提负债**，须进 EK 报表并按月披露。
- **防通胀：** 日上限 + 活动预算熔断 + 发放预算随材料价联动（价跌 10% 同步下调，协议保留调整权）。

### 7.6 提现资金池与对账

资金池须 ≥ 未来 7 天预计提现额 × 1.5，低于阈值告警并暂停非必要返现。日对账三条线：① 账本 vs 支付通道；② 提现申请 vs 实际出款；③ 积分发放 vs 活动预算消耗。差异 > BRL 1.00 告警，> BRL 100 冻结出款并人工介入。手续费单列科目，不冲抵返现成本。

## 8. 风控与反欺诈

客户 §46 只覆盖"机器侧"（重复投瓶、条码伪造、材质不符）。App 侧风险面完全不同，须独立设计。

| 风险 | 手法 | 检测信号 | 处置 |
|---|---|---|---|
| 一人多号 | 虚拟号、接码批量注册 | 同设备多账号、同 IP 段注册突增、注册到首投 < 60s | 首投奖励延迟 7 天；同设备 > 3 号转人工 |
| 重复投瓶 | 同一瓶子反复投 | 同 GTIN + 同重量 2 分钟内重复；同会话重量分布异常集中 | 按 `eventId` + 指纹去重，命中不计分 |
| 刷单薅活动 | 集中时段冲榜 | 单日 > 250 件、单小时 > 80 件、活动末期尖峰 | 榜单剔除异常；奖励延迟 24h 结算 |
| 设备模拟 | 伪造 `X-Machine-Key` 直调 `/ingest` | 密钥来源 IP 白名单、时间戳偏移、事件速率超真实吞吐（≤ 30 件/分） | 密钥轮换；异常事件拒收并告警 |
| 提现洗钱 | 多账号汇聚同一 PIX key | 同 key 绑定 > 3 账号、提现后立即注销、收款人姓名与 CPF 不符 | 阻断提现、转人工、留存 5 年 |
| 账号接管 | 号码回收后重新分配 | 长期未登录（> 180 天）+ 新设备 + 立即提现 | 二次 OTP + 72h 冷静期 + 冻结提现 |

**规则阈值（初始值，按月回溯调优）：** 单用户日积分 > 500 → 超出不计分；单设备 30 天账号数 > 3 → 标记入队；同 PIX key 账号 > 3 → 阻断；提现后 24h 内注销 → 先审；注册到首投 < 30s → 奖励延迟；邀请转化率 > 80% 且被邀请人 7 天留存 < 10% → 暂停邀请奖励并审团。

**设备指纹：** 只用 IDFV（iOS）/ Android ID + 应用实例 ID；**禁止采集 IMEI、MAC、通讯录、剪贴板**；隐私政策披露，法律依据为正当利益（反欺诈），提供拒绝路径（拒绝仅限制提现额度，不阻断基础功能）。

**审核与申诉：** 自动拦截全部入人工队列，按"金额 × 置信度"排序，首响 ≤ 24h、结论 ≤ 72h。封禁分三级（限速 24h → 限提现 → 封号），封号须给原因码与申诉入口，申诉 5 个工作日内答复，误封补偿（恢复余额 + 200 积分）。所有风控动作写 `audit_logs`（规则 ID、命中值、操作人、时间），保留 5 年。

| 审计日志 | 全量、不可改、可检索 | 仅自己 | 仅自己 | 仅自己 |

**硬性要求：** ① 所有写操作记 `audit_logs`（actor、action、entity、before/after、IP、时间）；② 金额类操作（提现放行、强制作废、库存调整）需二次确认 + 双签；③ 导出明细不得含 CPF、手机号、完整姓名；④ 独立域名 + IP 白名单 + MFA。

## 14. 风险与开放问题

| # | 风险/问题 | 影响与建议 |
|---|---|---|
| 1 | **数据归属未定**：§24 要求 EK 拥有全部运营数据，但个人数据归数据主体，App 行为数据归属未写明 | 三层切分：设备运营数据（EK）、个人数据（主体，EK 为控制者）、匿名聚合（EK 商用），须写入合同 |
| 2 | **积分负债无会计口径** | 形成未披露负债（示例 BRL 78 万）；按月计提披露，"负债/月材料收入"设 1.5× 上限 |
| 3 | **PIX 直连 vs Stripe**：Stripe 跨境 payout 到巴西 PIX key 受主体与合规限制 | 首选本地 PSP（Pagar.me/Asaas/Celcoin）出款，Stripe 仅收单；MVP 保留 mock |
| 4 | **跨境数据**：中国团队需访问生产数据排障 | SCC + TIA + 巴西区域存储 + 脱敏跳板；禁止原始 PII 出境；ANPD 最高罚 2% 营收 |
| 5 | **品牌方结算**：Danone 等按 CPA/CPM 结算，缺标准对账单 | 定义结算单（活动 ID、合格投瓶数、去重规则、15 天争议窗口），月结出账 |
| 6 | **设备离线补偿**：离线期投瓶无法实时到账 | 本地存储 + 补传 + 24h 自动补偿（FR-21），否则首次遇到即流失 |
| 7 | **汇率与材料价格波动** | 参数季度复核；价跌 10% 触发下调（协议保留调整权） |
| 8 | **白标定制成本** | 多租户 + 主题包 + 功能开关 + `depositMode`，定制只在配置层 |
| 9 | **促销授权（SPA）**：带奖品的排名活动可能需官方授权 | 上线前法律意见书；优先"人人有券"替代"仅第一名有奖" |
| 10 | **手机号回收致账号接管** | 余额被盗、品牌受损；三重验证 + 72h 冷静期 |
| 11 | **iOS 因外部支付被拒** | 上线延期；提前书面预沟通，备 IAP 方案 |
| 12 | **活动峰值与整机吞吐冲突** | 排队、体验下降；按楼栋分批放开 + 实时状态提示 |

**待客户确认（Pilot 前闭环）：** ① 单件积分规则由 EK 还是场所定？② 场所补贴是否进积分预算？③ 迷你超市结算周期（T+7 或月结）？④ 是否接受 16+ 门槛？⑤ 品牌方是否接受奖励延迟 7 天？⑥ CO₂ 系数采用哪套标准？⑦ 白标客户是独立包名还是同包多租户？⑧ 删除与税务留存如何裁决（见 9.3）？

## 16. 用户未提到但必须补上的需求

以下 16 项在原问卷中未出现，缺失将导致上线后出现法律、资金或信任事故。

| # | 需求 | 为什么必须补 |
|---|---|---|
| N1 | **手机号回收与账号接管防护** | 巴西号码重复分配率高，纯 OTP 下旧号新主可接管账户提现；需三重验证 + 72h 冷静期 |
| N2 | **积分过期与到期召回** | 12 个月过期是控负债核心手段，无 T-30/T-7 提醒会被视为骗积分 |
| N3 | **活动预算硬熔断与一键下线** | 倍率写错一次即超发数月材料收入；需预算上限、告警、30 秒下线 |
| N4 | **离线投瓶补偿与争议工单** | 机器离线是常态（§22），无补偿则首次遇到即永久流失 |
| N5 | **财务日切与三方对账** | 账本、通道、银行流水差异须 T+1 发现，否则负债与资金池双双失真 |
| N6 | **提现分级 KYC 与反洗钱留存** | Lei 9.613/98 强制客户识别与 5 年留存，问卷未提 |
| N7 | **促销活动授权与奖品税务** | 带奖品排名可能触发 SPA 授权与 IRRF 代扣，属"做活动前"问题 |
| N8 | **未成年人保护与监护人同意** | LGPD Art. 14 有专门要求，提现须 18+，缺失会在审核与抽查中暴露 |
| N9 | **数据留存矩阵与删除/留存裁决** | §20 要求删除、税法要求留 5 年，不裁决则工程无法实现 |
| N10 | **白标多租户与 `depositMode` 开关** | 把"积分"硬编码进模型，欧洲二期等于重写 |
| N11 | **广告标识与原生卡片区分** | CONAR + CDC 禁止隐性广告，活动卡片与功能卡片同构有合规风险 |
| N12 | **实物奖品 7 天无理由退货与运费规则** | CDC Art. 49 强制，缺失时投诉到 Procon 的成本高于商品本身 |
| N13 | **设备指纹的合规边界** | 采 IMEI/通讯录属过度采集，须限定 IDFV/Android ID 并做 DPIA |
| N14 | **品牌方标准结算单与争议窗口** | 无结算单则活动收入无法确认，直接卡住现金流 |
| N15 | **ANPD 事故响应预案（3 个工作日）** | 通报有硬时限，无预案时第一反应往往是隐瞒，后果更重 |
| N16 | **客服双通道与资金类 SLA** | 巴西用户依赖 WhatsApp，仅邮件工单无法达成 48h 资金争议 SLA |
